## The problem

Cycle-tracking apps routinely send intimate health data to third-party servers and advertising SDKs. Users who want the tracking often do not want the data collection that normally comes with it.

## The approach

A Flutter application built so that sensitive data does not need to leave the device to be useful. Feature-first architecture keeps each domain self-contained, and the design system is specified through screen and component contracts so behaviour stays consistent as the app grows.

## Architecture

| Component | Responsibility |
| --- | --- |
| **Feature modules** | Self-contained domains with their own entities and screens |
| **Domain layer** | Entities and rules independent of UI |
| **Design contracts** | Screen and component specifications driving implementation |
| **Local persistence** | On-device storage for sensitive records |

## FAQ

### What makes it privacy-first?

The architecture treats the device as the system of record for sensitive entries, so the app is useful without shipping intimate data to a server.

### Why Flutter?

One codebase across platforms with full control of rendering, which matters for a design-led health app.

### Is it published?

The implementation is in a private repository; access can be arranged.

### Who is it for?

Users who want cycle and wellness tracking without the data collection typical of the category.
